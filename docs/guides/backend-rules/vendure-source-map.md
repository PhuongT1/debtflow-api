## Traced flow A: Customer create/update

1. V04/V05 declare the transport input and expected result union; generated argument types are imported by V01.
2. V01 binds RequestContext and arguments, declares the specific permission and wraps a mutation in a transaction.
3. V12 normalizes identity input, checks conflicts/channel ownership, coordinates related user/history/custom-field work, persists and publishes typed events.
4. V14–V16 explain how the same transaction manager reaches repository calls through context.
5. V26 distinguishes ordinary commit-aware event subscribers from blocking in-transaction handlers; V27 defines the customer event payload.
6. V22–V25 cover foreign-channel mutations, invalid business input and precise patch behavior.

DebtFlow mapping: runtime request DTO → controller with authenticated context/roles → feature service → tenant-scoped Prisma operations using the transaction client → safe audit event after transaction resolution → global REST response/error envelope. There is no transport or transaction identity between the two implementations.

## Traced flow B: Product/Role read and access

V02/V03 bind requested list/options/relations and permissions. V29/V12 scope the query by channel and soft-delete rules. V17/V18/V30 centralize query capability parsing rather than accepting arbitrary database expressions. V13 computes visible roles before paging and deliberately uses fresh role data when authorizing grants. V08 separately checks owner-related address IDs; a broad permission alone is not resource ownership.

DebtFlow mapping: role/context gate → trusted organization base condition → resource list-query allow-list → matching scoped count/items and stable order. Role checks, record ownership and active membership are separate requirements.

## Adaptation decisions

| Evidence                                                | Required DebtFlow adaptation                                                                                                                                                           |
| ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GraphQL schemas/generated args (V04–V06)                | Concrete REST DTO classes with class-validator, runtime imports, public response DTOs and regenerated OpenAPI. Do not claim Vendure uses the same DTO pipeline.                        |
| Permission/channel/owner checks (V07–V08, V12–V13, V28) | Existing JWT active-member checks + organization roles + explicit organization/related-ID scope. Channels can share entities; organization-owned rows do not automatically share them. |
| TypeORM transaction context (V14–V16)                   | Prisma 7 `$transaction`/`Prisma.TransactionClient` propagated to every dependent write. Do not add a second ORM or imitate a decorator without its runtime machinery.                  |
| Event delivery (V26–V27)                                | Emit after the actual Prisma transaction resolves. Current best-effort audit is not Vendure commit-aware observable delivery or a durable outbox.                                      |
| Files/helpers/module exports (V01–V03, V19–V20)         | Kebab-case role-named files inside existing feature ownership; explicit Nest provider ownership. Detailed DTO suffixes are DebtFlow conventions.                                       |
| Query builder and tests (V17–V18, V22–V25, V30)         | Reuse shared query parser/caps, typed capability definitions, concrete rejected input and tenant/HTTP boundary tests.                                                                  |
